# Microduck 3v3 足球赛升级规划

> 规划时间 2026-09-05

## 概述

将当前 Microduck Arena（单鸭子演示）升级为 3v3 足球对战系统，参考 Booster Champion 3v3 仿真赛规则。

## 当前能力盘点

### 已有能力 ✅
- [x] 浏览器内 MuJoCo WASM 物理仿真（50 Hz 控制循环）
- [x] ONNX 策略推理（行走、踢球、站立等 7+ 策略）
- [x] 可踢足球（ball-actor.js 已有球物理 + 视觉）
- [x] 3D 渲染 + 入场动画 + 音效系统
- [x] 多人幽灵系统（WebRTC P2P）
- [x] 键盘 / 手柄 / 触屏 / 路径点多种控制方式
- [x] Zustand 状态管理 + React UI 层
- [x] Tron grid 场地渲染（shader）
- [x] 鸭子模型（14 关节，GLB mesh）

### 缺失能力 ❌
- [ ] 多鸭子实例（当前仅 1 只 + 幽灵视觉）
- [ ] AI 决策层（当前是人工控制，需要自主决策逻辑）
- [ ] 足球规则系统（进球、出界、角球/门球/边线球）
- [ ] 球场标线 + 球门（当前是方形 arena，无球门）
- [ ] 比赛计时 / 计分 / 状态机
- [ ] 多 Agent 协同（3 台机器人配合）
- [ ] 自动裁判系统
- [ ] 红黄牌 / 罚时机制

## 分阶段实施计划

### Phase 1：场地改造（预计 2-3 天）

**目标**：将 3×3m arena 扩展为带球门的足球场

#### 任务清单

1. **扩展场地尺寸**
   - 文件：`app/src/game/constants.js`
   - 修改：`ARENA_HALF` 从 1.5 改为 ~3.0（6m 长）
   - 新增：`FIELD_WIDTH = 4.0`（4m 宽）
   - 新增：`GOAL_WIDTH = 1.2`（球门宽度）
   - 新增：`GOAL_DEPTH = 0.3`（球门深度）

2. **添加球门**
   - 新建：`app/src/game/goal.js`
   - 功能：
     - 球门 mesh（两根门柱 + 横梁）
     - 球门碰撞体（MuJoCo geom）
     - 进球检测区域
   - 位置：场地两端中线位置

3. **场地标线**
   - 文件：`app/src/game/arena.js`
   - 新增 shader uniform：
     - 中线
     - 中圈（半径 0.6m）
     - 罚球区（球门前 1.2m × 0.8m）
     - 角球区（四角 0.3m 半径圆弧）
   - 复用现有 grid shader 语言

4. **墙壁改造**
   - 文件：`app/src/game/arena.js`
   - 修改：两端墙壁留出球门开口
   - 保留：两侧墙壁完整

#### 验收标准
- [ ] 场地尺寸 6m × 4m
- [ ] 两端各有一个球门（宽 1.2m）
- [ ] 场地有中线、中圈、罚球区标线
- [ ] 球可以进入球门并触发检测
- [ ] 球门有碰撞体，球可以反弹

### Phase 2：多鸭子 + AI Agent（预计 3-5 天）

**目标**：实现 6 只鸭子（3v3 红蓝两队）+ 简单 AI 决策

#### 任务清单

1. **多鸭子实例化**
   - 文件：`app/src/game/duck.js`、`app/src/game/game.js`
   - 修改：
     - `buildRig` 支持批量创建
     - 每只鸭子独立物理状态（qpos/qvel）
     - 每只鸭子独立 ONNX 推理会话
   - 新增：
     - 鸭子编号（0-5）
     - 队伍标识（红队 0-2，蓝队 3-5）
     - 角色标识（前锋/后卫/门将）

2. **AI 决策层**
   - 新建：`app/src/game/ai/`
   - 文件结构：
     ```
     ai/
     ├── agent.js       # Agent 基类
     ├── forward.js     # 前锋 AI
     ├── defender.js    # 后卫 AI
     ├── goalkeeper.js  # 门将 AI
     └── utils.js       # 工具函数
     ```
   - AI 输入（仿真真值，与 Booster 一致）：
     - 球位置 (x, y)
     - 球速度 (vx, vy)
     - 队友位置 [(x, y), ...]
     - 对手位置 [(x, y), ...]
     - 己方球门位置 (x, y)
     - 对方球门位置 (x, y)
   - AI 输出：
     - 速度命令 (vx, wz)
     - 踢球触发（boolean）

3. **前锋 AI 逻辑**
   ```
   状态机：
   - 追球：球距离 > 0.5m → 面向球移动
   - 对准：球距离 < 0.5m → 面向对方球门
   - 射门：对准角度 < 15° → 触发踢球
   - 回位：无球且远离位置 → 回到进攻位置
   ```

4. **后卫 AI 逻辑**
   ```
   状态机：
   - 防守位置：保持在己方半场
   - 拦截：球向己方球门移动 → 拦截
   - 解围：球距离 < 0.5m → 向对方方向踢球
   ```

5. **门将 AI 逻辑**
   ```
   状态机：
   - 站位：在球门线上跟随球 y 坐标
   - 扑救：球速度指向球门且距离 < 1.5m → 侧向扑救
   - 复位：球远离 → 回到球门中心
   ```

6. **多机协同**
   - 前锋 + 后卫配合：
     - 前锋持球时后卫前压
     - 后卫持球时前锋前插
   - 避免碰撞：
     - 队友距离 < 0.3m 时互相避让

#### 验收标准
- [ ] 6 只鸭子同时在场上（3 红 3 蓝）
- [ ] 每只鸭子有独立 AI 控制
- [ ] 前锋会追球、射门
- [ ] 后卫会防守、解围
- [ ] 门将会跟随球、扑救
- [ ] 红蓝两队能自主对战

### Phase 3：足球规则引擎（预计 2-3 天）

**目标**：实现完整的足球比赛规则 + 自动裁判

#### 任务清单

1. **比赛状态机**
   - 新建：`app/src/game/referee.js`
   - 状态：
     ```
     IDLE → KICKOFF → PLAYING → DEAD_BALL → (SET_PIECE | GOAL) → PLAYING
     ```
   - 事件：
     - 进球
     - 出界（边线/底线）
     - 犯规
     - 倒地超时

2. **进球检测**
   - 条件：球整体越过球门线（在球门范围内）
   - 处理：
     - 记录得分
     - 切换到 DEAD_BALL
     - 准备重新开球

3. **出界检测**
   - 边线球：球 x 坐标超出 ±FIELD_WIDTH/2
   - 底线球：球 y 坐标超出 ±FIELD_LENGTH/2
   - 判断最后触球方 → 决定球权

4. **定位球系统**
   - 角球：球从底线出界（防守方最后触球）
   - 门球：球从底线出界（进攻方最后触球）
   - 边线球：球从边线出界
   - 开球：进球后 / 比赛开始

5. **犯规检测**
   - 倒地超时：鸭子倒地 > 5 秒未起身
   - 长时间无活动：球在鸭子 3m 范围内但鸭子不动 > 10 秒
   - 定位球违规：未等裁判哨声提前触球

6. **罚时系统**
   - 犯规 → 罚下 30 秒
   - 罚时期间鸭子变灰 + 移出场地
   - 罚时结束 → 鸭子回到边线

7. **红黄牌**
   - 2 次警告 → 黄牌
   - 2 次黄牌 → 红牌（永久罚下）

#### 验收标准
- [ ] 进球能正确计分
- [ ] 出界能正确判给球权
- [ ] 角球/门球/边线球能自动执行
- [ ] 犯规能触发罚时
- [ ] 比赛能完整进行（开球→进球→重新开球）

## 技术要点

### 多物理实例
- MuJoCo WASM 支持多模型，需要独立 `mjModel` + `mjData`
- 每只鸭子独立 `qpos` / `qvel` 数组
- 碰撞检测：鸭子-鸭子、鸭子-球、球-球门

### AI 决策频率
- 物理仿真：50 Hz
- AI 决策：10 Hz（每 5 帧决策一次）
- 减少计算量，避免卡顿

### 状态同步
- 物理状态：每帧同步到 three.js mesh
- AI 状态：决策后缓存，下一帧使用
- UI 状态：通过 Zustand 同步（节流 4 Hz）

### 性能优化
- 6 只鸭子 + 1 个球 = 7 个物理实例
- ONNX 推理：6 个会话（或批量推理）
- 渲染：复用几何体，不同材质区分队伍
